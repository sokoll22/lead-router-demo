# Lead Router — демка для агентств

Заявка приходит свободным текстом (сайт, почта, чат) → превращается в структурную
запись для CRM → команда получает уведомление за секунды, а не когда кто-то вручную
разберёт письмо.

Два способа показать: **веб-страница** (её показывают клиентам и пишут на видео) и
**CLI** (для проверки пайплайна).

---

## Запуск веб-версии

```bash
cd ~/DemoProjects2026/lead-router-demo
pip install -r requirements.txt
python3 app.py
```

Открыть <http://127.0.0.1:5001>. Порт 5001, а не 5000, потому что на macOS 5000
занят AirPlay Receiver.

**Перед записью видео выставить ключ** — тогда разбор идёт настоящей моделью:

```bash
ANTHROPIC_API_KEY=sk-... python3 app.py
```

Без ключа страница работает в офлайн-режиме (эвристика на регулярках). Пайплайн
показывает целиком, но качество извлечения ниже, и время разбора получается
неправдоподобно маленьким (единицы миллисекунд) — на видео это выглядит хуже,
чем честные 1-2 секунды у модели.

### Что на странице

- Слева — поле для текста заявки и три готовых примера.
- Справа — извлечённые поля, время разбора против «~6 минут вручную», сводка и
  превью уведомления, которое получила бы команда.
- **Наведение на поле подсвечивает место в письме, откуда оно взято.** Поля
  помечены `quoted` (дословная цитата) или `inferred` (вывод модели). Это главный
  ответ на возражение «а оно не выдумывает?».
- Ничего не сохраняется: текст живёт в памяти на время запроса, на диск не
  пишется и никуда не отправляется. Для агентства это критично — оно не имеет
  права отдавать данные своего клиента в чужой сервис (GDPR).

## Запуск CLI

```bash
python3 main.py --input sample_leads --batch     # все примеры
python3 main.py --input sample_leads/lead_1.txt  # один
```

Пишет запись в `crm_records.json` и уведомление в `notifications.log`
(оба в `.gitignore`).

## Как это устроено

```
текст заявки
     │
     ▼
extractor.py   поля: имя, компания, контакт, тип проекта, бюджет,
     │         срочность, суть. Режимы: llm (Anthropic API) / mock (регулярки)
     ▼
   crm.py      запись в CRM. В демо — локальный JSON; для клиента меняется
     │         на Airtable/HubSpot/Notion заменой одного модуля
     ▼
 notifier.py   уведомление. В демо — консоль и лог; для клиента —
               Telegram/Slack/email (заготовка в комментарии внутри файла)
```

`app.py` — веб-обёртка над тем же `extractor.py`, свою копию логики не держит и
намеренно не использует `crm.py`/`notifier.py`: на странице ничего не сохраняется.

Для реального клиента меняются только `crm.py` (какая у него CRM) и `notifier.py`
(какой канал) — логика извлечения не трогается.
